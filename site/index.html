  1. 01

    Scan or paste

    The QR holds an install link: lawallet:plugin?url=… pointing at a plugin folder on GitHub. Only HTTPS GitHub links are accepted, and a scan never installs anything on its own.

  2. 02

    Pinned to a commit

    The app resolves the branch to the exact commit it read right now. Manifest and bundle come from that commit, so what you review is what runs.

  3. 03

    Review every permission

    The sheet lists each host it connects to, where you sign in, whether it keeps a login, and how often it checks for payments. Nothing is downloaded until you tap Install.

  4. 04

    A wallet in your deck

    Sign in on the provider's own page (LaWallet never sees the password) and the wallet joins your Lightning deck: balance, transfers, and Pay from when the plugin supports it.

Isolation

A sandbox that says no by default.

Own QuickJS context

Its own thread and a 32 MB heap. No file system, no imports, no app objects. A stuck plugin gets stopped, and the app keeps running.

Host allowlist

HTTPS only, and only to the exact hostnames in the manifest. No redirects, no cookies, no LaWallet credentials.

SHA-256 checked

The bundle's hash is recorded at install and checked on every load. If the file changes, it doesn't run.

Encrypted secrets

Tokens are encrypted with an Android Keystore key and kept per plugin id. Removing the plugin wipes them.

No payment without you

pay_invoice is only called after you confirm on LaWallet's own Send screen. A plugin can't start a payment.

Your keys stay yours

No plugin ever sees your nsec, NWC connections, Lightning address or LaWallet session.

Build

One file. Ship a wallet.

A manifest that declares what it touches, and an ES module that answers NIP-47 calls with host.fetch, host.secrets and host.webLogin. Use TypeScript or npm, bundled into a single index.js.

Build with an agent

Describe a wallet. Get a plugin on your emulator.

The lawallet-plugin skill teaches an agent the whole loop. It clones android-wallet, puts a debug build on the Android emulator, scaffolds a plugin and tests it offline, then installs and reloads it in the running app.

  1. 01

    Install the skill

    Claude Code loads skills from ~/.claude/skills.

    terminal 
    $ git clone --depth 1 {{REPO_URL}} /tmp/lwp
$ mkdir -p ~/.claude/skills
$ cp -R /tmp/lwp/skills/lawallet-plugin ~/.claude/skills/
  2. 02

    Start the agent

    In an empty folder, with Opus 5.5.

    terminal 
    $ mkdir -p ~/lawallet-dev && cd ~/lawallet-dev
$ claude --model claude-opus-5-5
  3. 03

    Ask for a plugin

    Name the provider and link its API docs.

    /lawallet-plugin Set up LaWallet for Android on the emulator, then build a plugin for <Provider>. Their API docs: <link>. Install it on the emulator when its tests pass.

lwdev setuplwdev applwdev servelwdev newlwdev testlwdev install

You sign in to the app once, and to the provider on its own page. The agent never sees a password. It works on a side-by-side .preview copy, so a real wallet is never touched. Full guide
